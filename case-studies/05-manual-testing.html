Manual Testing

End-to-end manual testing for anonymized enterprise web apps: Product names are omitted for NDA compliance; linked artifacts are redacted samples.

At-a-glance results

Coverage

~180 test cases across smoke, regression, and UAT flows.

Defects caught pre-release

28 (7 P1, 0 P0) before production cut.

Cycle time

Regression cycle reduced from 3d → 1.5d with better modularization.

Scope & Context

  • Contract platform: user roles, clause library, workflow approvals, billing, and export.
  • Data portal: secure auth, registry forms, document upload/preview, reports, and consent.
  • Objectives: solid smoke for PR reviews, deep regression per release, and UAT sign-off with traceability.
  • Constraints: multi-env setup, PII rules, and strict audit trails (timestamps, actor, reason).

Test Strategy (manual-first)

  • Requirement walkthrough → identify user stories, risks, and data permutations.
  • Test design → modular test cases mapped to stories (traceability matrix).
  • Execution cycles → smoke (daily), regression (pre-release), UAT (stakeholder scripts).
  • Bug triage → severity/priority, repro evidence (screens, HAR, logs), fix/verify loop.
  • Exit criteria → all P0 closed, P1 mitigated, smoke 100% pass, high-risk areas retested.

Test Types Covered (manual)

Smoke / Sanity Auth, nav, create/read core entities, critical happy paths.
Functional (positive/negative) Form validations, boundary values, RBAC, idempotency, error messaging.
Integration / Workflow Multi-step approvals, webhooks/jobs confirmation (UI evidence), email templates.
Usability Clarity of labels, empty states, destructive action safeguards, undo/rollback paths.
Accessibility (manual checks) Keyboard order/focus, visible focus states, headings hierarchy, alt text, ARIA labels.
Compatibility Chrome/Firefox/Edge (desktop); responsive checks for key views (tablet, mobile).
Data & Security basics Role isolation, no sensitive data in URLs/logs, session timeout/reauth flows.
Localization / Formatting Dates, numbers, currency; timezones/DST where applicable.
Regression All high-risk modules + recent bug buckets retested before release.
UAT Stakeholder scripts: business scenarios, acceptance notes, sign-off record.

Example Manual Test Case (snippet)

ID: REG-ACL-014
Title: Approver can approve a submitted contract
Preconditions: User A (Author), User B (Approver); draft contract exists
Steps:
  1) Author submits contract for approval
  2) Approver receives notification and opens contract
  3) Approver reviews, adds comment, clicks "Approve"
Expected:
  - Status changes to "Approved"; audit log shows actor, timestamp, comment
  - Author receives confirmation; export is enabled
Notes:
  - Negative: Approver without permission sees disabled action with tooltip
  - Evidence: screenshots + audit log entry ID

Process & Traceability

  • Mapping: Every test case links to a user story/requirement ID; summary report lists coverage and open risks.
  • Evidence: Screenshots, HAR files, and logs attached to defects; summary includes pass/fail counts by module.
  • Release gate: 100% smoke pass; no P0 open; P1 risk accepted by product; retest of fixes verified.

Results (Before → After)

  • Regression cycle time: 3 days → 1.5 days (modularized cases, clearer data setup)
  • Missed edge-cases in approvals: 5 → 0 (added negative + role-based tests)
  • UAT rework items per release: 10 → 3 (early walkthrough + checklists)
