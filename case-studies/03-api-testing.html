API Testing

Functional testing for REST APIs across anonymized enterprise web apps. Product names omitted for NDA compliance.

At-a-glance results

Schema/Contract Catches

0 → 6 breaking changes caught pre-merge (first month) via contract tests.

Error Rate (release week)

2.1% → 0.6% (4xx/5xx) after negative coverage & validation on PR.

p95 Latency (smoke)

~620ms → ~410ms on critical read endpoints (with thresholds in CI).

Scope & Context

  • Public + authenticated REST endpoints: auth, search/list, details, create/update, and export.
  • Primary risks: silent contract drift, pagination bugs, insufficient negative coverage, and auth/session edge cases.
  • Targets: stable PR gates, clear failure signals, and traceable evidence (reports, logs) for fast fixes.

Test Design

  • Collections & Folders: one folder per resource (/auth, /users, /records, /search, /export).
  • Positive paths: happy-path CRUD, pagination/sorting, filters, and role-based access.
  • Negative/abuse: invalid/expired tokens, malformed JSON, boundary values, rate-limit and idempotency checks, missing fields.
  • Contract tests: JSON Schema for requests/responses + selective consumer-driven checks for critical fields.
  • Data strategy: seeded tenants/users, isolated IDs per run, teardown or idempotent writes to avoid collisions.

Tooling & Conventions

  • Postman collections/environments, Newman in CI for batch runs with JUnit/HTML reports.
  • Schemas: versioned in repo under schemas/; validated in Postman tests.
  • Variables: BASE_URL, TOKEN, TENANT_ID, request-scoped UUIDs for uniqueness.
  • Secrets: tokens pulled in CI from encrypted secrets (never committed).

Examples

Pre-request: fetch token

// Pre-request script (Postman)
pm.sendRequest({
  url: pm.environment.get("AUTH_URL"),
  method: "POST",
  header: { "Content-Type": "application/json" },
  body: { mode: "raw", raw: JSON.stringify({
    client_id: pm.environment.get("CLIENT_ID"),
    client_secret: pm.environment.get("CLIENT_SECRET"),
    grant_type: "client_credentials"
  }) }
}, (err, res) => {
  pm.expect(err).to.equal(null);
  const token = res.json().access_token;
  pm.environment.set("TOKEN", token);
});

Contract test (response schema)

// Tests tab (Postman)
const schema = {
  type: "object",
  required: ["id", "name", "createdAt"],
  properties: {
    id: { type: "string" },
    name: { type: "string", minLength: 1 },
    createdAt: { type: "string", format: "date-time" },
    meta: { type: "object" }
  },
  additionalProperties: true
};
pm.test("schema is valid", function () {
  pm.response.to.have.jsonSchema(schema); // uses Postman's built-in JSON schema validator
});
pm.test("status is 200", () => pm.response.to.have.status(200));

Negative case: malformed payload + auth

// Tests tab (Postman)
pm.test("rejects malformed JSON", function () {
  pm.response.to.have.status(400);
  const body = pm.response.json();
  pm.expect(body.error || body.message).to.exist;
});
pm.test("requires auth", function () {
  // In a separate request without Authorization header
  pm.response.to.have.status(401);
});

CI/CD Integration

  • PR gate (Newman): run smoke + contract folders; fail the check on any test error or schema violation.
  • Nightly: full suite including negative, pagination, and edge-case flows; upload JUnit/HTML reports as artifacts.
  • Thresholds (optional): assert p95 duration on selected endpoints via a short k6 smoke (separate job) to catch perf regressions.
Newman in GitHub Actions (example) 
name: api-tests
on:
  pull_request:
  workflow_dispatch:
jobs:
  newman:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 18 }
      - run: npm i -g newman newman-reporter-htmlextra
      - name: Run smoke + contract
        env:
          BASE_URL: ${{ secrets.BASE_URL }}
          AUTH_URL: ${{ secrets.AUTH_URL }}
          CLIENT_ID: ${{ secrets.CLIENT_ID }}
          CLIENT_SECRET: ${{ secrets.CLIENT_SECRET }}
        run: |
          newman run postman/collections/api.postman_collection.json \
            -e postman/environments/ci.postman_environment.json \
            --folder "smoke" --folder "contract" \
            --reporters cli,htmlextra,junit \
            --reporter-htmlextra-export newman/report.html \
            --reporter-junit-export newman/junit.xml
      - uses: actions/upload-artifact@v4
        with:
          name: newman-reports
          path: newman/**
